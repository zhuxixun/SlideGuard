🔒

完全离线 · 零信任隐私

不依赖任何云端 API、大模型服务或在线账号。所有计算在浏览器沙箱内完成，断网与联网体验一致。客户方案、投标材料等敏感内容零泄露风险。

📋

系统性全量扫描

从「单页辅助」升级为「跨页系统性检查」。不仅检查单页字体和对齐，还能识别跨页面标题位置偏差、页码缺失、页脚不一致、模板风格漂移等全局问题。

🔍

可解释的智能分析

每个问题都展示具体触发原因与量化依据，如"标题横坐标与同类页平均位置偏差32px""该页颜色数高于中位数2.4倍"。禁止输出"AI认为不美观"等黑箱结论。

🔧

检测 + 修复闭环

不仅发现问题，还可对字体替换、元素对齐、标题样式等确定性执行一键批量修复。修复后自动重新扫描，输出前后对比，形成完整闭环。

检测规则与全流程闭环

7 项检测规则 + 3 类自动修复的完整闭环

所有检测与修复全部在浏览器本地执行，规则引擎驱动确定性检查，不依赖任何大模型 API 或云端服务。

⚙️ 规则引擎（7 项检测规则）

  • 空白页面检查 — 识别无主体内容的页面
  • 页面外元素检查 — 画布外文字与图片检测
  • 字体一致性检查 — 标准字体：微软雅黑 可修复
  • 元素对齐检查 — 同组元素对齐偏差检测 可修复
  • 文字安全边距检查 — 文字是否过度靠近页面边缘
  • 标题一致性检查 — 字体 / 加粗 / 颜色统一 可修复
  • 敏感及残留文本检查 — 精确匹配用户敏感词库

🔧 全流程能力闭环

  • 三种扫描模式：快速 / 标准 / 自定义灵活组合
  • 问题分级 S1–S4 + 多维筛选 + 关键词搜索
  • 页面预览 + 问题元素红框高亮 + 判断依据展示
  • 一键自动修复：字体替换 / 元素对齐 / 标题样式
  • 修复后自动重新扫描，输出前后对比报告
  • 修复结果保存为新文件，原始文件始终不变

AI 协同开发实践

Agent 实践总结：用 AI 协同开发 SlideGuard 的启示

本次项目全程采用 AI Agent 辅助开发模式，分别使用了两套不同的 AI 工具链进行对比实践。

🤖 Codex + GPT-5.6-sol

定位：设计决策 + 复杂 Bug 修复

GPT-5.6-sol 消耗：约1.5亿 ~ 2亿 tokens

🦾 Claude Code + DeepSeek-v4(flash/pro)

定位：主力实现编码 + 增量迭代

DeepSeek-v4-flash/pro 消耗：1.9亿 tokens

📌 五点经验

1
明确分工：GPT 负责设计决策 + 复杂 Bug 修复，DeepSeek 负责主力编码实现
2
通用要求沉淀到 CLAUDE.md：项目规范、架构决策记入文件，新 session 自动加载
3
主动 compact：上下文太长模型变笨，及时 /compact 或 /clear
4
一句话只问一个问题：有前后依赖关系的需求，一步一步来
5
完成一个需求就开新 session：避免旧上下文污染后续任务

🎯 核心结论

没有银弹，但有好流程。 为任务匹配合适的模型、将通用要求写入文件、保持上下文精炼、分步骤推进 —— 这才是 AI 辅助开发效率最大化的关键。
